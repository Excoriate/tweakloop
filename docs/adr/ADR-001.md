# ADR-001 — Immutable facts and rebuildable projections

## Status

Accepted

## Context

Tweakloop must preserve four things independently: the artifact revisions that existed, the human intentions expressed against them, the agent work performed in response, and the evidence and decisions that determined acceptance. Mutable session state (the Lavish model: one mutable file plus one session object) braids these together, loses feedback under concurrent updates, and cannot be replayed, branched, or recovered independently.

## Decision

Durable truth is an append-only event log with a compact vocabulary (`intent.created`, `work.claimed`, `evidence.recorded`, `decision.accepted`, ...). Facts are never updated or deleted — they are superseded by new facts. All "current" state — current revision, unresolved feedback, approvals, verification status — is derived by deterministic projection reducers into disposable, `p_`-prefixed tables. `tweak repair --rebuild-projections` replays the log and replaces projections only when invariants hold. Explicitly named ephemeral tables (`review_drafts`, `runtime_leases`, `browser_presence`, `projection_offsets`) hold working state that does not belong in history.

## Alternatives rejected

- One mutable JSON session file (braids identity, feedback, presence, diagnostics; untransactable).
- One global status enum per intent (submission, execution, verification, and acceptance are independent dimensions).
- A generic event-sourcing framework (imposes aggregate/repository abstractions bigger than the domain; use an explicit event table, explicit reducers, explicit SQL).

## Consequences

Replay tests are mandatory: incremental and full-rebuild projections must be equal. Event schemas evolve additively, with readers/upcasters for old versions instead of event migrations. Timeline, audit, and diff views come nearly free. More upfront modeling is required for every feature (fact, command, decision, projection).

## Falsifier

If projections routinely diverge from replayed state, or the event vocabulary churns so fast that upcasting dominates development, the fact model is wrong for this domain.

## Migration path

Additive event evolution with upcasters; projections rebuilt at will; the log itself ports behind the `Store` interface if the storage engine changes.
