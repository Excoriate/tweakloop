# ADR-004 — Project, workspace, artifact and revision identity

## Status

Accepted

## Context

Identity is not location. Files move, repositories are cloned, worktrees coexist, multiple artifacts may derive from one source, and "latest" is a moving target. Paths, selectors, ports, PIDs, and browser tabs are locators, not identities. File-path-as-identity produced workspace-isolation and parallel-worktree problems in prior art.

## Decision

Maintain five distinct identities:

| Identity | Meaning | Persistence |
|---|---|---|
| `project_id` | Logical project shared across clones/worktrees | `.tweakloop/project.json`, safe to commit |
| `workspace_id` | One local worktree or directory instance | Local state directory (`$XDG_STATE_HOME/tweakloop/workspaces/<id>/`) |
| `artifact_id` | Logical artifact across revisions | Event store |
| `revision_id` | One immutable occurrence in artifact history | Event store |
| `content_hash` | Identity of exact bytes | Content-addressed store |

IDs are random UUIDs; the database `seq` provides ordering. `project.json` holds only stable, non-secret metadata. `runtime.json` (PID, ports, nonce) is an ephemeral locator, never authoritative state.

## Alternatives rejected

- File path as artifact identity.
- "Latest" as revision identity.
- PID, port, or browser session as agent/work identity.

## Consequences

Registration and workspace-discovery machinery is required. Clones, parallel worktrees, and moved files stop corrupting review history. Two worktrees of one project are two workspaces sharing one `project_id`.

## Falsifier

If artifacts never span workspaces and every project has exactly one clone, the identity indirection is pure overhead.

## Migration path

`project.json` evolves additively under `schemaVersion`; identity relationships extend with new mapping facts, never by redefining existing IDs.
