# ADR-002 — One daemon and serialized transactor per workspace

## Status

Accepted

## Context

SQLite permits many concurrent readers but only one simultaneous writer; WAL mode lets readers continue against snapshots while a writer appends. Prior art shows what happens without a single authority: a state-storage race in Lavish could lose feedback when multiple sessions updated a shared state file concurrently. Multiple processes (CLI invocations, browser workers, agent adapters) must not race on durable state.

## Decision

Run one daemon per Git worktree or explicit non-Git workspace. The daemon owns the SQLite write connection, the workspace runtime lock, the event sequence, artifact watchers, browser listeners, agent claims, and the artifact server. All durable mutations pass through a single serialized transactor executing the fixed pipeline: validate envelope → check idempotency receipt → load stream state → check expected stream version → call the pure `decide` function → `BEGIN IMMEDIATE` → append events → update synchronous projections → record receipt → commit → publish to observers. CLI processes never open the database directly; they discover the daemon via the runtime descriptor (health endpoint plus process nonce) and start it under a startup lock on OS-assigned loopback ports.

## Alternatives rejected

- Direct multi-writer SQLite access from CLI, browser workers, renderers, or plugins.
- Microservices (the first authority boundary is one local workspace; module boundaries suffice).
- Kafka, Redis, or Postgres (an embedded single-writer workload does not justify network infrastructure).

## Consequences

A trivially correct local total order (`seq`). Command throughput is serialized — acceptable at local scale. Daemon lifecycle machinery (discovery, nonce verification, atomic runtime descriptor writes, startup locking) is required and must be tested for crashes.

## Falsifier

A real multi-machine or high-concurrency multi-writer requirement that a single local transactor cannot serve.

## Migration path

The transactor and command envelope are the stable seam; the storage engine behind them can become a server database without changing the protocol.
