# ADR-010 — Agent execution remains outside the daemon

## Status

Accepted

## Context

A review daemon that executes arbitrary shell commands — for verification, implementation, or browser-triggered agent runs — becomes a privileged local remote-code-execution surface. Tweakloop's browser renders untrusted agent-generated HTML; combining that with a command runner would put RCE inside the initial trusted computing base.

## Decision

The daemon does not execute arbitrary commands, does not modify repository files, does not host models, and does not orchestrate prompts in v0.1. Agents run inside their existing harnesses (Claude Code, Codex, OpenCode, or any process that can invoke the CLI), edit repositories there, and interact with Tweakloop only through the versioned CLI/command protocol: claim work, read intents and manifests, publish revisions, record results, and attach evidence. Verification commands are run by the agent harness; the daemon records the resulting evidence immutably. The core has no agent-specific code paths — harness skills and hooks are discovery adapters, not architecture.

## Alternatives rejected

- A daemon-side verification runner in v0.1.
- Automatic agent execution triggered from the browser (transforms a review tool into a privileged command-execution system).
- Agent-specific core integrations (any CLI-capable agent must be able to participate).

## Consequences

Tweakloop's trusted boundary stays small and auditable. Verification depends on harness cooperation; missing evidence is visible state, never interpreted as passing. Repository modification remains outside the daemon (architecture invariant 20).

## Falsifier

If evidence submission friction is so high that unverified "done" claims dominate real usage, the boundary is starving the verification model.

## Migration path

A future opt-in runner may be added behind a separate capability boundary: explicit user authorization, command allowlists, and isolated execution — as its own ADR.
