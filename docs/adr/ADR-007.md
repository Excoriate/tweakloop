# ADR-007 — Typed intents with free-form fallback

## Status

Accepted

## Context

Free-form prose forces agents to interpret what the human meant; ambiguity survives every round trip. The highest-leverage difference over annotation tools is that agents receive unambiguous operations. But not all feedback is typeable, and forcing structure everywhere would suppress legitimate observations.

## Decision

Provide a typed intent vocabulary as versioned schemas — `comment`, `question`, `replace-text`, `remove`, `move`, `choose`, `reject-option`, `add-constraint`, `approve-node`, `request-implementation`, `request-verification`, `accept-result`, `reopen` — with free-form `comment` as the explicit fallback, not the primary channel. Intents are immutable values: never rewritten, only superseded (`intent.superseded`) or cancelled. Drafts accumulate in the browser and commit atomically as one review batch (`review.batch-submitted` plus intent events plus work-item creation). Approval is revision-specific: it binds a semantic node's content digest at a revision; later changes show the approval as invalidated in projections, never mutate it.

## Alternatives rejected

- Free-form-only annotations attached to DOM locations (the Lavish model — agents interpret prose).
- One braided status enum on intents (submission, disposition, execution, verification, and acceptance are independent dimensions).
- Mechanically prohibiting changes to approved nodes (only an explicit human constraint may do that).

## Consequences

The shell must offer structured capture UI per intent type. Agents receive machine-readable targets and payloads via the CLI. Adding an intent type means adding a schema, a decision path, and projection handling — deliberate friction that keeps the vocabulary compact.

## Falsifier

If users overwhelmingly stay in free-form comments and typed intents see no adoption, the structured vocabulary is ceremony.

## Migration path

New intent types are additive schemas; existing intents remain readable; retired types stay parseable via upcasters.
