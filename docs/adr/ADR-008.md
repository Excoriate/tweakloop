# ADR-008 — Durable work claims with ephemeral leases

## Status

Accepted

## Context

One agent long-polling one file loses workflow state when the agent crashes, hands off, or runs in parallel with others. Work must survive process death, prevent double execution, and make abandonment visible — without polluting domain history with heartbeat noise.

## Decision

Work items reference intent IDs, the reviewed base revision, dependencies (`dependsOn` only — no DAG scheduler in v0.1), and expected verification. Claiming is atomic and produces a durable `work.claimed` event; the active lease lives in an ephemeral table (`work_id`, `claim_id`, `agent_id`, `process_nonce`, `expires_at`, `last_heartbeat_at`). Heartbeats renew the lease record only. Only one non-expired lease exists per work item. Expired work becomes claimable; reclaiming records `work.abandoned` for the previous claim. Completion requires the claim ID; stale-claim completion is rejected. There is no global "agent working" lock — humans submit feedback freely while agents work; agent presence is informational, never a synchronization primitive.

## Alternatives rejected

- Long-polling as the central coordination model (queue must not depend on a waiting process staying alive).
- Heartbeats as durable events (noise in the fact log).
- A general DAG scheduler in v0.1.

## Consequences

Concurrency tests must prove no work item ever has two live claims and that abandoned work recovers. Crash of a claimed agent becomes visible state (`work.abandoned`), not silence. `tweak work claim --wait` can idle cheaply because the durable queue outlives the waiting process.

## Falsifier

If usage is strictly single-agent and sequential, lease machinery is ceremony a simple flag could replace.

## Migration path

Priority, capability matching, and richer scheduling layer onto the same claim/lease events without changing their meaning.
