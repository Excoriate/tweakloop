Tweakloop Taskbar

dogfood iteration · reviewed in the live shell · comment to agent from any semantic section

Overview

A stable, Google-Docs-inspired collaboration workspace: Documents and the active document's outline live together on the left; the immutable artifact remains dominant in the center; one persistent Agent rail on the right keeps comments, their derived tasks, agent progress and chat in a single causal loop. The reviewer never leaves the artifact to discover what is happening.

Assumptions — correct these first

  • Each document is the parent of its own revision-specific semantic outline.
  • At narrow widths, Documents become a horizontal strip and Agent becomes a persistent bottom sheet — neither is stacked after the artifact.
  • Comments are the anchored human input; Tasks are a projection of durable Work, never a second checklist database.
  • Workspace connectivity, agent availability, claim ownership and human acceptance remain separate truths.

Tasks checklist

The persistent Agent rail renders Tasks as a projection over Work, Intent, Claim and Result: ○ queued, ◐ working by agent and ✓ addressed. The compact Dynamic Tasks summary keeps the selected comment/current claim and remaining count as the visual anchor. Each Task links to its source Comment and semantic target; no copy or client-side task identity exists.

Decision: segmented mode control

Interact/Comment becomes a two-segment pill (Docs-style) instead of a toggle button whose label flips. Rationale: a toggle labeled "Mode: Comment" is ambiguous (state or action?); segments show both options and the active one. Push back if you preferred the single button.

Decision: keyboard shortcuts

Proposed: E toggle mode · F fullscreen · [ collapse Documents · ] open the Agent sheet · ⌘Enter send an anchored comment or chat message. There are no collaboration-panel shortcuts because there are no collaboration modes to switch.

Risks

  • Rail becomes a dashboard — keep the selected comment/current work dominant; collapse old history before adding panels.
  • Cross-document leakage — key outlines by viewed revision and drafts/composer state by artifact.
  • False live state — workspace transport, connected agent listeners, transient activity, delivery, claim, result and acceptance are independent truths. A connected listener remains Available after thinking or working expires; multiple listeners are reference-counted so one disconnect cannot hide another.

Rollout

1) Browser prototype the Documents/artifact/Agent geometry. 2) Submit a real anchored comment here and observe the same Work become the Dynamic Task. 3) Harden thread identity, originating-agent assignment, process-scoped leases, reconnect and accept/reopen behind the proven interaction. 4) Use the resulting loop to dogfood the local whiteboard migration as an independent delivery slice. 5) Chrome, e2e, offline and restart proofs gate owner review.
