Ephemeral work leases, heartbeat/expiry, and work claim --wait

Today a claimed work item stays claimed forever: if the agent process exits after tweak work claim, the work is stranded and no other agent can pick it up. This is documented as the top Phase 3 remainder (deviation #10 in 16-implementation-status.md) and it blocks the Phase 3 exit condition: "two concurrent fake agents cannot claim the same work, and abandoned work recovers."

This feature adds, per the section 13.3 design:

  • an ephemeral lease attached to every durable work.claimed fact, with a TTL;
  • tweak work heartbeat to extend the lease while an agent is actively working;
  • abandoned-work recovery: an expired lease makes the work claimable again, and the reclaim records a durable work.abandoned fact for the previous claim;
  • tweak work claim --wait so agents can block until work exists instead of hand-rolling sleep loops (as the tweakloop skill currently instructs).

Current state (what we build on)

  • work.created / work.claimed / work.addressed events exist; decide() already enforces atomic single claim and rejects stale-claim completion (src/domain/decide.ts).
  • The transactor is a serialized single writer with injected now/newEventId deps, so domain purity is preserved when time enters a decision.
  • work.abandoned is listed as an owed event in the information model — the vocabulary slot is reserved, not yet implemented.
  • The SKILL.md workflow tells agents to poll work claim with manual sleeps — --wait replaces that.

Decision — where the ephemeral lease lives decision

OptionTrade-off
A. SQLite table work_leases (as sketched in §13.3), excluded from the fact log and from projection rebuilds Leases survive daemon restarts, so a restart doesn't instantly strand or free in-flight work; single-writer transactor keeps lease insert atomic with the work.claimed append. Slightly more storage code.
B. In-memory map in the daemon Less code, but every daemon restart silently expires all leases — an agent that heartbeats on schedule can still lose its claim, which violates "no silent recovery" in spirit.
Recommendation: A. It matches the architecture doc verbatim, and lease loss then only happens by real expiry, which is always recorded as an explicit work.abandoned fact at reclaim time.

Decision — heartbeats are ephemeral, not facts decision

A heartbeat every ~30 seconds must not append to the event log — it would bloat the append-only fact history with operational noise ("ordering is not wall-clock"; heartbeats carry no meaning worth replaying). Proposed rule: only work.claimed, work.abandoned, and work.addressed are durable facts; heartbeats mutate only the work_leases row (expires_at, last_heartbeat_at).

Consequence for the HTTP surface: heartbeat cannot go through the ordinary command → event pipeline (commands there produce facts). It becomes a small auxiliary route, POST /api/v1/work/:workId/heartbeat, CLI-token-gated, in the same spirit as the existing auxiliary routes (/bootstrap-tokens, /shutdown) already recorded as deviations #3.

Decision — how work claim --wait blocks decision

OptionTrade-off
A. CLI subscribes to the existing SSE stream; attempts a claim on start and again whenever a work.created / work.abandoned event arrives, with a periodic fallback retry (~15 s) in case the stream drops Near-instant pickup, zero new daemon state, reuses transport the architecture already chose (POST + SSE). Slightly more CLI code.
B. Daemon-side long-poll endpoint that parks the request until work exists Simpler client, but reintroduces held-connection state in the daemon — the very thing §29.4 rejected WebSockets for.
Recommendation: A. The wait loop lives entirely in the CLI; the daemon stays stateless about waiting agents. Add --timeout <seconds> (default: wait indefinitely; on timeout exit with {"status":"none"}).

Phase 1 — Domain src/domain

  • Add the work.abandoned event: { workId, claimId, agentId, reason: "lease-expired" | "cancelled" } (reason vocabulary kept open for the future supersede/cancel work).
  • Extend the work.claim decision: the transactor passes lease status (active / expired / none) for each claimed item into decide() alongside now. A claim over an expired lease emits work.abandoned (old claim) + work.claimed (new claim) in one transaction; a claim over an active lease still rejects.
  • evolve(): work.abandoned clears the claim on the work state so existing stale-claim completion rejection covers the abandoned agent returning late (it gets work.stale-claim, honest and explicit).
  • No domain change for heartbeat — it never reaches the domain (see decision above).

Phase 2 — Storage src/storage

  • Migration: work_leases table — work_id (PK), claim_id, agent_id, process_nonce, expires_at, last_heartbeat_at — exactly §13.3's sketch.
  • Lease rows are written in the same transaction as the work.claimed append and deleted on completion/abandonment. The table is ignored by repair --rebuild-projections (it is ephemeral state, not a projection; rebuilding facts never touches it).
  • Default lease TTL: 120 s, configurable per claim via --lease-ttl. Heartbeat guidance: every 30 s (TTL/4).

Phase 3 — HTTP + CLI + skill src/daemon, src/cli

  • POST /api/v1/work/:workId/heartbeat (body: claimId, agentId) → { expiresAt }; rejects unknown/stale claims explicitly.
  • Claim responses gain leaseExpiresAt so agents know their deadline.
  • CLI: tweak work heartbeat <workId> --claim <claimId> --agent ... --json; tweak work claim --wait [--timeout <s>] [--lease-ttl <s>] per the wait-mechanism decision.
  • Update skills/tweakloop/SKILL.md: replace the sleep-and-retry guidance with --wait, and add the heartbeat obligation for long-running revisions.
  • Update docs/architecture/16-implementation-status.md when the feature lands.

Phase 4 — Tests test, e2e

  • Domain tables: reclaim of an expired lease emits abandoned + claimed; reclaim of an active lease rejects; completion with an abandoned claim rejects with work.stale-claim; replay of the new events rebuilds identical state.
  • Transactor: two concurrent claims — exactly one wins and exactly one lease row exists; lease row lifecycle across claim → heartbeat → complete.
  • Crash recovery: claim, simulate agent death (no heartbeats), advance past TTL, second agent reclaims; the event log shows the full explicit history.
  • e2e: extend review-loop.spec.ts (or add a sibling spec): agent A claims and goes silent, agent B runs work claim --wait, receives the work after expiry, completes it; the shell sees the completion over SSE.

Risks and non-goals

  • Clock authority: only the daemon's clock decides expiry (single process, single writer) — no distributed-clock concerns; agents receive leaseExpiresAt as advisory.
  • TTL too short for real agent work: revising a large artifact can exceed 120 s, which is why heartbeat exists — but an agent that forgets to heartbeat loses work honestly (recorded as work.abandoned). Mitigation: SKILL.md makes heartbeat an explicit obligation, and the TTL is configurable.
  • Non-goals (deferred, per roadmap): supersede/cancel commands, dependsOn ordering, evidence objects, human-facing lease UI in the shell beyond showing the abandonment events that already flow over SSE.

Acceptance criteria

  1. Phase 3 exit condition passes: two concurrent fake agents cannot claim the same work, and abandoned work recovers — proven by the transactor and crash tests above.
  2. An abandoned agent returning late gets an explicit work.stale-claim rejection, never a silent overwrite.
  3. tweak work claim --wait returns within ~1 s of a review batch being submitted (SSE-triggered), and respects --timeout.
  4. Full history (claims, abandonments, completions) survives daemon restart and repair --rebuild-projections; the lease table's absence after a wipe is handled by the explicit expiry path, not silent recovery.
  5. The event log after the e2e run reads as an honest narrative: created → claimed(A) → abandoned(A, lease-expired) → claimed(B) → addressed(B).
