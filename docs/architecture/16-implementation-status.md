## The v0.1 vertical slice (§30) — running

The complete human-review loop is exercised in a real browser for HTML, Markdown, and standalone Excalidraw artifacts: an originating agent opens the artifact → the human opens the bootstrap-authenticated shell, sees the immutable revision on the isolated artifact origin, comments on a precise semantic target → the assigned agent claims the typed work with a recoverable lease, revises/publishes, and completes it → the shell shows “ready for review” rather than pretending completion is acceptance → the human accepts or reopens explicitly. The Markdown browser lane independently proves source publication, semantic comment targeting, task creation, CLI claim, immutable Markdown revision, live readiness, rendered replacement text, and human acceptance. Chat, tasks, whiteboard drafts, revisions, and decisions arrive live over SSE, and the event log records the durable loop. The collaboration rail is one accessible tab interface: Chat opens by default and Chat, Tasks, and Comments are mutually exclusive views rather than three compressed feeds competing for the same space.

## Design-law compliance (verified against code)

- **Values over mutable places** — `events` is append-only; no `UPDATE`/`DELETE` targets it anywhere in `src/`. Projections (`p_*`) are the only mutable tables, and `tweak repair --rebuild-projections` rebuilds them from facts (`src/daemon/projections.ts`).
- **Identity is not location** — artifacts have `artifact_<uuid>` identities with `sourcePath` stored as a locator; the workspace id is a stable local handle; ports/PIDs live only in the ephemeral `runtime.json`.
- **Ordering is not wall-clock** — `seq` (database autoincrement) orders everything: SSE ids, `--after` replay, projection rebuild. `recordedAt` is metadata.
- **Current state is derived** — the transactor folds `decide`/`evolve` over stored events; `p_*` tables are disposable; the shell renders snapshot + events only.
- **Effects at the edges** — `src/domain/` imports nothing but its own modules; IDs and timestamps enter via `TransactorDeps` (`newEventId`, `now`).
- **Protocols are data** — `tweakloop.command/v1` envelope + per-command payload JSON Schemas in `src/protocol/schemas/`, validated with ajv at the boundary.
- **No silent recovery** — duplicate registrations are explicit rejections (`artifact.already-registered`, `artifact.source-already-registered` with the existing id in `details`); stale expected versions reject with `concurrency.version-conflict`; a dead daemon is detected by start-nonce mismatch, never assumed alive.

## Declared deviations (all additive; none contradict the design)

1. **Flat domain modules.** `src/domain/commands.ts` (etc.) are single files rather than section 24's subdirectories. Boundaries and dependency direction are identical; files split into directories when their contents warrant it (build discipline: no speculative structure).
2. **`runtime.json` carries a `cliToken`.** The runtime descriptor (section 5.2) additionally holds a bearer token, file mode 0600 — filesystem permissions are the local authority that lets the CLI (and agents) call the daemon API. Browser access still requires the one-time bootstrap flow.
3. **Two auxiliary shell routes.** `POST /api/v1/bootstrap-tokens` (CLI-token-gated minting for section 22's bootstrap flow) and `POST /api/v1/shutdown` (backs `tweak daemon stop`). The artifact origin still has zero mutation routes.
4. **Same-origin check instead of a CSRF token.** Cookie-authenticated mutations require exact `Origin` + host-allowlist match — the "equivalent same-origin request token" permitted by section 22.
5. **`GET /api/v1/events` also serves JSON.** With `Accept: text/event-stream` it streams SSE; otherwise it returns the committed events as a JSON array (used by `tweak events list`). Same data, same ordering.
6. **`workspace.opened` is recorded once per workspace**, via the durable idempotency receipt `workspace.open:<workspaceId>` — repeat opens are receipt replays, not new facts.
7. **`Decision` is a result value.** `decide()` returns `{ ok: true, events, response } | { ok: false, code, message, details? }` — rejections are values, not exceptions, which section 7.2's sketch left implicit.
8. **`tweak repair` runs in-process only while the daemon is stopped.** The single-writer rule holds: whichever process runs it is the sole writer at that moment.
9. **Unit tests use vitest** (section 23.1 permits "a similarly minimal runner"); Playwright covers the browser slice (`just e2e`).
10. **Claims are durable; liveness is ephemeral.** `work.claimed`/`work.abandoned` remain durable facts while heartbeat/expiry live in the lease table. An expired claim is recoverable and stale completion is rejected; presence never substitutes for ownership. A claimed-work `session listen --presence working --until-work-settled` co-process keeps socket-backed Working and one exact claim lease live until settlement, without creating `work.progressed` or granting durable authority. Renewal rejection or claim replacement terminates that listener and removes Working while leaving durable work unchanged.
11. **`POST /api/v1/publish` is a composite ingestion endpoint.** Register-if-unknown + object-store snapshot + `artifact.publish` run daemon-side so the CLI never touches the database or object store; every durable effect still flows through ordinary commands.
12. **Markdown is a first-class projection.** `.md`, `.markdown`, and `.mdown` use deterministic heading ancestry and stable block anchors; unsafe raw HTML and URLs stay inert. Exact source-range re-anchoring remains future work.
13. **`.agents/skills/` is the canonical source for the three portable OSS skill packages.** A standalone projector copies that tree to the package-facing `skills/` and Claude discovery under `.claude/skills/`. Its dedicated `.agents/skill-projection-lock.json` rejects ordinary consumer drift before replacement; the clean-room test runs with no contributor-specific harness manifest, lock, guide generator, hook, or task-state convention, and its dynamic canonical inventory makes every newly added skill part of projection and package validation automatically. Personal workflow tooling is an optional downstream consumer of Tweakloop's public protocol, never an authority for skill source, projection, packaging, installation, or release acceptance, and no personal harness command is exposed through the public package, Justfile, or Quickstart. The projection lock is a local drift guard, not a signed trust root against a hostile same-user editor; the direct reverse-edge guard rejects named private workflow surfaces but is not claimed to understand obfuscated or arbitrary skill prose. Projection/package parity proves portable bytes only, while installed-client discovery and exact body assimilation require separate version-pinned probes. The optional public v2 Stop adapter binds one active native conversation to an exact Tweakloop session/runtime generation and performs only read-only observation; its packaged configurator can generate one explicit project-local client file but activates nothing by default, so repository-native client configs remain absent. Current installed-client probes produced real Stop callbacks for Claude Code and Codex; the installed Cursor Agent completed trusted-workspace turns without invoking its documented project Stop hook. Cursor activation therefore remains unproved, and stopped-client launch, explicit progress, and universal user-visible effect remain separate unproved boundaries. Guide centralization is an independent product-owned projection: `.agents/AGENTS.md` is canonical, root `AGENTS.md` is the drift-checked generated consumer, `CLAUDE.md` must remain its symlink, and the default `just check` runs `check-guides` without any private renderer or task-state dependency.
14. **Live chat is a durable event family** (`chat.message` via `chat.send`), not ephemeral presence: messages may carry a quoted selection `context` and whole-artifact `mentions` (@-file references). Agents can read a session snapshot then listen from its exact sequence; the shell renders committed messages live over SSE.
15. **Rollback is republication.** `POST /api/v1/restore` (and `tweak restore`, which also syncs the source file from the edge) publishes a prior revision's content as a new head — history is never rewritten, and the daemon never writes to the repository.
16. **Whiteboards are Excalidraw data + a local runtime.** Standalone `.excalidraw` artifacts and strict immutable Markdown references share one renderer. The pinned, code-split Excalidraw runtime is served locally with no CDN. Mutable CAS drafts use versioned optimistic writes and SSE; conflicts retain both sides until explicit resolution; publication creates an immutable revision. A narrow one-way tldraw importer exists only for legacy data.
17. **Agent sessions are durable lineage, not browser presence.** Immutable start/handoff/end facts rebuild `p_sessions`; each document-queryable takeover packet derives origin/current agent identity, stable process nonce, predecessor/successors, goal/summary, base/head/session revisions, correlated work and intents, complete chat, and related whiteboards. `session resume` creates a successor. Live presence and claim leases remain separate ephemeral truths.
18. **Semantic scene commands are the normal basic-diagram path; managed native files are the advanced path.** `tweak whiteboard scene add-node|add-edge|set-label|group|layout|inspect|publish` keeps renderer identity and geometry server-owned. Non-empty groups render one locked, unlabeled enclosure derived from exact membership; the closed inspect ABI still exposes only group semantic keys and members, never renderer state or a label field. `tweak whiteboard workspace checkout|sync|publish` remains available for native-scene edits beyond the semantic builder; low-level draft/CAS commands remain diagnostic/conflict primitives.
19. **`skills/excalidraw/SKILL.md` is a focused discovery adapter.** It adds board-specific triggers and a concise managed-workspace operator card for standalone and embedded Excalidraw artifacts, while cross-linking `skills/tweakloop/SKILL.md` for the complete session/work/review protocol. Its presence proves packaged instructions, not fresh-agent activation or usability.
20. **The collaboration rail is a view switcher, not a dashboard stack.** Chat is the persisted default; Chat, Tasks, and Comments use one ARIA tablist with one active tabpanel, arrow/Home/End keyboard movement, deterministic focus, and a working expand/restore control. Closed comments leave the active view but remain recoverable through the activity history.
21. **Typed chat context is durable and content-addressed.** Browser paste/file attachments and CLI `--attach` store immutable blobs; `@` references identify documents, revision-pinned selections, comments, tasks, individual boards, or all boards by stable identifiers. The event records hashes and metadata, not ephemeral browser file handles.
22. **Session delivery is workspace-shaped.** A session listener consumes durable chat, work, revisions, and decisions across every participating document; `--artifact` narrows whiteboard draft traffic but does not silently discard other session traffic. Agent/process assertions are optional when the durable session already supplies them. Explicit socket-backed presence may be `listening`, `thinking`, or exact-claimed-work `working`; listener failure remains non-authoritative and socket close removes the ephemeral state.
23. **Whiteboard mutable retention is bounded without rewriting history.** Receipts, resolved conflicts, unresolved conflicts, and unreferenced workspace blobs have separate caps. Immutable revision and event-log roots remain protected, so cleanup cannot erase published history.
24. **Revision-ready notifications are explicitly user-controlled.** The shell models unsupported, denied, granted, and disabled states and requests browser permission only from the user action. OS banner presentation still depends on the browser and operating-system notification settings; tests prove the application routes and permission-state behavior, not every desktop notification center.
25. **Workspace export separates collaboration sequence from file quiescence.** The v2 bound envelope records collaboration `event-seq-exact` independently from an optional `quiescent-verified` file rail. File publication requires matching start/post-copy/pre-envelope closed-set fingerprints over membership, exclusions, type, identity, bytes, and mode. This is fail-closed sampled quiescence, not a kernel snapshot or joint cross-rail instant; v1 bound file bundles require re-export.
26. **Agent wake is turn-shaped, not daemon-shaped.** SSE still serves browsers and persistent consumers. `next --wait` gives an agent harness one bounded command that emits one item and exits; a durable offer is not called received until the exact response-only capability is acknowledged by the intended process.
27. **Working files are an explicit reconstruction policy.** `tweakloop.workspace-files/v2` selects relative include/exclude globs and optional notes. Hashes, sizes, modes, secret/managed-state exclusion receipts, symlink refusal, three closed-set observations, and stage-before-place restore keep file reconstruction separate from collaboration facts. Restored ABA and post-final-observation mutation remain explicit ceilings.
28. **Fork preserves values and replaces ownership.** An exact saved-session checkpoint preserves artifact/revision/content identity and ordered roles while minting new workspace, session, process, event, command, and correlation identities. Source identifiers remain provenance only; sibling forks have independent event histories.
29. **Questions are typed chat content, not a second workflow.** A choice question has 2–8 unique key/label options; an answer names the exact question and exact answer it supersedes. Session actor authority and current answer are derived from immutable facts. Asking or answering changes no work, intent, delivery, or human acceptance dimension.
30. **Agent scene authority is capability-holder provenance.** Session start/resume registers only a client-generated capability hash. Private client custody mints one-use, request-bound automation tokens; restart/resume rotates authority, and consume + scope revalidation + business idempotency + mutation share one transaction. No runtime authority is exported. This does not authenticate a physical model/process or resist a hostile same-user sibling that can read the holder's private secret.
31. **Human authority is browser-derived.** Decisions, comments, default-human chat, and accepted-work reopening execute through the authenticated shell. Their CLI surfaces return typed `human.browser-required`/`work.accepted-browser-required` failures with `mutated:false` and a deliberate `session url` continuation instead of mutating or printing a browser credential. Explicit agent chat and new/open intent tracking remain CLI operations.
32. **Scene inspection is a closed semantic projection.** `whiteboard scene inspect` returns only protocol and artifact identity plus semantic-key-ordered node, edge, and group collections. Explicit field selection prevents additions to internal semantic maps or renderer records from becoming public ABI: draft/base/hash/version state, renderer identity/bookkeeping, authority, paths, and URLs remain private.
33. **A client result cannot erase a durable commit.** New-session `open` performs validation-only custody preflight before publication. Once publication commits, any later setup failure returns `open.committed-partial` with the exact committed artifact/revision/seq and a state-conditioned recovery command. Its generic retry flag is false so automation cannot mistake durable mutation for an uncommitted failure; recovery must prove same-revision reuse.
34. **Workspace exact retry is caller-to-retention shaped.** Public export accepts a stable operation identity; fork consults the durable journal before treating an existing destination as a collision. The immutable result stays separate from a nullable current locator. `workspace restore-inventory` exposes quota/recovery evidence and `workspace restore-compact` deletes only after full generation, retained-state, and live-runtime validation.
